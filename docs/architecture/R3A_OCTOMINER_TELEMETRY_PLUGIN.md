## Parity and implemented R3A providers

| V2 capability | R3A provider and output | Evidence limit / state |
|---|---|---|
| GPU inventory, UUID/PCI/name/driver, utilization, VRAM, temperature, power, per-GPU fan | `plugin.py` fixed `nvidia-smi --query-gpu` over R3A strict-pinned SSH | Current direct collection is fresh; unsupported metrics remain null; no production read was made |
| Mounted filesystem capacity | `plugin.py` fixed `df -P -B1 -x tmpfs -x devtmpfs` | Source/mount/byte counts, no fleet deduplication; direct read fixture-tested |
| GPU process-to-device mapping | `process_providers.py` fixed NVIDIA compute-app query retains UUID, PID, process name, and GPU memory | PID-to-GPU is measured from NVIDIA source; model label is added only by an exact R3A `model_process_names` mapping with config digest and `configured` status; unmapped processes remain unmapped |
| Model-server readiness and active slots | `http_providers.py` fixed GET `/health` and `/slots` for each R3A-configured service; counts only `is_processing` values and returned slot records | No prompt content; endpoint retrieval time is used because source sample time is absent; missing/invalid fields are unavailable |
| ComfyUI health/version, queue, CUDA and VRAM | `http_providers.py` fixed GET `/system_stats` and `/queue`; extracts version/device capacity and only queue lengths | No queue entry/prompt data is returned; missing GPU fields stay null/unavailable |
| Provider call timing and prompt/completion counts | `grace_module.py` measures UTC start/end plus monotonic elapsed time around the R3A provider call and preserves provider-reported token counts; `request_metrics.py` reads only R3A durable model-turn JSON fields via a separately configured read-only DSN | Rate is completion tokens divided by summed provider-call time, including service/network overhead. Missing provider usage/time stays null. Native token rate is always unavailable |
| Streamed output character cadence | `request_metrics.py` computes cadence only from two or more timestamped application text deltas | Current Grace transport receives buffered JSON responses and records no deltas; cadence is explicitly unavailable. No token rate is inferred |
| Bounded time history and source freshness | `history.py` writes a local SQLite journal at the operator-provided path on each telemetry invocation, retains per-source samples for the configured rolling window, caps at a configured number per source and returns the latest configured count | Defaults in the example are a 300-second window, 128 stored samples/source, 8 returned samples, and a 64 MiB SQLite page limit. This is invocation-driven history, not a background five-second polling service. A failed read uses a recent last-good sample as `stale`; without a recent measurement it is `unavailable`. Live retrievals are `fresh`, with source timestamp limits shown separately |
| Bay mapping, chassis controller fans, environmental sensors, PSU, watchdog | Not collected | Archive marks these as unverified or unavailable; R3A emits no invented values |
| GPU workload actions | Not exposed | Capability is read-only |

R3A makes sources independent: a missing model endpoint does not suppress GPU/storage results; failures are returned per source. HTTP collection uses only fixed GET routes, disables ambient proxies and redirects, rejects public plain HTTP, limits response size, and keeps bearer tokens in configured environment variables. SSH accepts only the three fixed allowlisted read commands, disables ambient SSH config/forwarding/TTY, uses environment-resolved host/user/key/known-hosts settings, requires strict host-key verification, and bounds each call.

## Model-call provenance

The provider-call timestamp and elapsed duration are measured at the R3A HTTP request boundary. Token counts come only from the configured provider's returned usage object. That object is preserved and augmented with an `r3a_measurement` block; CME already persists the usage object in its `model_turns` projection. The telemetry provider uses a separate environment-provided read-only R3A DSN and selects only activity ID/state, reasoning model-turn arrays, token usage, references and timestamps. It does not select objective input, prompts, model response text, or capability payloads. The database role must be scoped to SELECT on the required R3A activity fields/table.

The current R3A transport is buffered rather than streaming. The cadence parser is fixture-tested for future timestamped R3A deltas, but live R3A produces none, so cadence remains unavailable. The telemetry output names provider-call completion tokens/s and never presents it as native inference speed.

## Configuration, history and authorization

`manifest.json` currently exposes the capability through the `r3a.resident-capability-tool` adapter expected by this branch's CME invocation path. It is not yet the agreed unified operation descriptor; the proposed migration is tracked in #46 coordination. The adapter's `read_only: true` means `effect_class: read`; it conveys no grant. Its configuration contains environment-variable names/references for host, SSH user/key/known-hosts, service endpoint URLs/tokens, R3A database DSN and local history path; no deployment path or credential value is baked into runtime code. Populate `model_process_names` only from reviewed host process evidence. Per-module artifacts are digest-pinned in the manifest, including provider helpers.

The generic loader in `r3a_runtime/config.py` validates manifest and supporting-artifact digests plus manifest-declared configuration schema. No CME-specific collector code changed for these providers. CME dynamically discovers the tool and applies its existing configured-capability and explicit grant checks. Discovery does not grant permission. The end-to-end demo test `tests/test_r3a_telemetry_inbox_demo.py` exercises that normal Grace action contract through a queued activity using fake model/store/provider responses; it does not connect to a database, model service, OctoMiner, or shared R3A runtime.

## Verification boundary and blockers

Focused fixtures verify NVIDIA and `df` parsing, pinned SSH arguments, model slots, ComfyUI queue privacy and CUDA capacity, NVIDIA process-to-GPU identity and configured model mapping, exact token/time usage, unavailable native rate, timestamp-gated stream cadence, bounded/stale history, manifest artifact pins, and the simulated autonomous inbox flow. No live credentials are present in this development environment. Live probes therefore remain unperformed; model service endpoint/token environment variables, R3A read-only database DSN, local history path, SSH key and pinned host keys must be independently provisioned before live operation. The tracked deployment configuration must pin the updated `grace_module.py` digest after integration approval. Nothing is activated by this branch.
