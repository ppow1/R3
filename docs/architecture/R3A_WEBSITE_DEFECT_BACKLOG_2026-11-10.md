## Conversation interface increment — 2026-11-10

The conversation view now presents individual message cards without an enclosing transcript card, offsets resident replies, and uses a single header row with normalized speaker name, local Eastern time to the second, small delivery-state icon, and an expandable right-side action menu. Copy uses the browser clipboard API and reports permission failures. Details expands source/status information. Editing, deleting, image generation, work assignment, and conversation rename/archive/delete are visibly disabled with explanatory accessible titles because the current API does not implement these operations. Generic backend titles are rendered as a resident plus localized creation time. The resident picker shows names and a green/red/unknown availability dot without printing resident IDs or machine status enums. Composer handling sends on Enter and retains Shift+Enter and IME composition. Completed/blocked results appear on the selected conversation through authenticated durable-history polling; polling backs off to 8 seconds and continues for up to 80 checks (about ten minutes) to cover the known cold-start interval. Network failures preserve loaded history and reconnect automatically.

The sidebar also polls the authenticated `/api/v1/steward/about` contract and reports Website API, Ring0, CME, Grace module health, freshness/check time, and whether model readiness is omitted by the API. This endpoint does not report inference-model readiness, so the UI explicitly says it is not reported; it does not infer readiness from Grace module status. The client has no stream endpoint and continues to use durable message snapshots, not simulated token streaming.

Permanent regression evidence: `node --test tests/test_steward_workspace_api.mjs` — 20 tests pass, including a mounted fake DOM check for speaker/time/status, toolbar expansion, copy/details availability, disabled unsupported actions, and the existing resident-selection race. This proves client behavior only. The live service at the captured deployment revision `e2fe437d02dfef75f6d9a08a64c46e806bacebeb` is not replaced by these source edits; the authenticated browser workflow remains unverified and deployment/restart is intentionally deferred to Coordinator V2.

## Continuation increment — after `ad9fd9a`

Resident-directory state now refreshes through the existing versioned same-origin API every 15 seconds when reachable, retrying after five seconds when unavailable. Only `freshness: current` can show green availability or enable chat creation/sending; stale/unavailable evidence pauses sending while retaining history and names. The indicator gives the last confirmed check time. The current directory display name takes precedence over an ID-shaped sender field. When availability returns, the selected durable transcript is refreshed. A revision guard prevents an in-flight directory response from restoring resident information after session revocation, and revocation resets the availability indicator. This uses the existing authoritative directory API and adds no Website-side resident identity map or authorization path.

Python API tests run without modifying the shared service environment by using the existing isolated interpreter: `/home/admin1/R3/.venv/bin/python -m unittest tests.test_r3a_website` passes 20 tests. `node --test tests/test_steward_workspace_api.mjs` passes 20 client tests. Persistent rename/archive/restore/delete and authenticated genuine streaming remain backend dependencies; no client-only pretend mutations are added. See the acceptance runbook and API requirements in [the conversation handoff](R3A_WEBSITE_CONVERSATION_UX_HANDOFF_2026-11-10.md).

## Fix delivered in this increment

`web/steward-workspace-api.mjs` now ignores conversation-list and history responses when their resident/conversation selection has changed while the request was pending. It also prevents a completed create/send request for the previous resident from changing the current view, attributes blocked-turn status to the current directory resident, and disables selection when the authoritative directory is empty. `web/index.html` now reads the authorized effective configuration when the Website session is verified, making the configured presentation timezone available to chat without visiting Settings first. `tests/test_steward_workspace_api.mjs` exercises deliberately reordered resident-list and message responses, dynamic blocked-turn labels, and empty directory state; the Website API test checks the timezone initialization hook.
