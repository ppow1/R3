## Package and handoff acceptance

The Website and R3A runtime currently share the `r3_app:app` deployable entrypoint. A Website-only Python wheel would omit application entrypoint, HTML/JavaScript, route adapters, and AP3/R3A runtime contracts; the approved package shape is therefore a commit-pinned source release bundle with the locked runtime dependency file and existing deployment assets. `scripts/deployment/package_r3a_website.py` produces a deterministic archive, an in-archive SHA-256 manifest for every included file, and an external archive digest. It excludes only the unused visual concept ZIP and records that exclusion in the manifest. The first isolated candidate attempt exposed that `requirements-deploy.lock` omitted the runtime's `psycopg`, binary wheel, and pool dependencies even though `pyproject.toml` declares them. Those exact CPython 3.12 Linux wheel hashes are now generated from downloaded wheel bytes with `scripts/deployment/generate_dependency_lock.py`; the focused package suite asserts all three packages remain pinned.

Build/verify commands (run in a non-production staging directory):

```sh
python scripts/deployment/package_r3a_website.py build \
  --source . --commit <exact-40-character-commit> \
  --output /tmp/r3a-website-<commit>.tar.gz
python scripts/deployment/package_r3a_website.py verify \
  --package /tmp/r3a-website-<commit>.tar.gz \
  --sha256 <digest-from-sidecar>
```

The bundle is not activated by its builder. Coordinator handoff uses the existing exact-SHA candidate builder and loopback verifier (`scripts/deployment/prepare_candidate.py`, `scripts/deployment/verify_candidate_runtime.py`), the locked requirements file, [LAN deployment runbook](../runbooks/R3A_LAN_HTTPS_DEPLOYMENT.md), and Coordinator-owned service lifecycle. Install/rollback stays Coordinator-controlled: stage a fresh release from the immutable source SHA; verify it; only the service owner may change the active working directory and restart the Website unit; rollback restores the previous exact Website source/config revision and restarts only that Website-owned unit after validation. This dispatch did not stage into the active tree, alter external config, deploy, or restart a service.
