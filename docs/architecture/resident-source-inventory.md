## Reconciliation of the record-count discrepancy

The count describes different stores and stages:

1. The historical HR executive summary (2026-11-05) described the initial two R3 records, Grace and Marie, with broader roster reconciliation explicitly pending.
2. The available local legacy HR SQLite snapshot now has 13 records. Eleven match public charter roles; two are protected/private. These are personnel rows with onboarding status, not proof of active office occupation.
3. The R3A directory contract reads a separate PostgreSQL authority schema whose rows represent offices and current occupant bindings. It neither reads nor imports HR files. A directory result with only Grace would mean only that the queried snapshot exposed that binding; it would not mean only one HR/personnel record exists. Conversely, 11 HR rows do not establish 11 active directory bindings.
4. R3A's documented local DSN is unconfigured in this worktree and no live directory snapshot could be reproduced. Its code returns `availability=unavailable` and empty arrays when unconfigured. Thus this work did not establish why a previously observed live query showed Grace, nor authenticate that observation's timestamp/schema/digest.
5. No synchronization/import/crosswalk from legacy HR SQLite to `riverview_authority` is documented or present in the local R3A code. IDs differ (`r3:grace` vs `resident.grace`) and remain unresolved until an authoritative mapping is supplied.

The safe disposition is to preserve all source records, exclude protected/private records from Git, mark the 11 published dossiers provisional, and require an authoritative directory snapshot plus HR crosswalk before declaring full coverage or activation readiness.
