### Status key

- **PASS (contract):** contract provides the required boundary; implementation/live status is separate.
- **GAP:** absent, contradictory, or insufficiently defined interface relative to an approved requirement or an explicitly proposed clarification. Proposal-only gaps do not create a FAIL against historical work.
- **PARTIAL:** some contract obligations exist, with named missing semantics.
- **NOT VERIFIED:** insufficient evidence for implementation/runtime conformity.
- **N/A:** outside modular integration scope.

## Verified Coordinator 722a102 result

### Source-level compliance: roster separation

The changed CME discovery code now treats directory membership as roster evidence, appends every well-formed resident returned by an authoritative measured/fresh directory snapshot, and no longer calls `require_capability` or compares a resident ID with CME module ID while building the roster. The Website no longer filters `authorized === false`; it displays directory rows and disables rows unless the service reports `chat_available === true`. The changed source adds no Grace/Vicky/Helen identity special case. This resolves the specific roster visibility coupling without weakening authorization at the invocation path.

### Remaining source gap: readiness and primary binding

The new status fields are currently constants (`unknown`, `unavailable`, `not_evaluated`, `false`, and one fixed diagnostic). They are conservative at the current reported state, but they are not a dynamic readiness evaluation. The UI therefore cannot enable chat even if a future resident is correctly onboarded and authorized. Treat the roster correction as complete, and the end-to-end “ready residents participate generically” requirement as incomplete.

Conversation creation revalidates measured directory membership. For residents other than `self.module_id`, it checks configured office routing plus both delegation and target execution grants. The target objective path again resolves the current directory profile and checks those grants before CME schedules work. These are source-level positive controls. The primary equality exception remains a separate risk: creation skips those checks when a directory `resident_id` equals CME `module_id`, while the approved resident execution profile has no registered module binding reference. Source equality alone should not represent authoritative identity binding. No evidence in this commit proves a live bypass or active authorized conversation; require the owner to make and document the intended primary-resident authorization case.
